# CXZ · Telegram-поиск бизнесов — версия 0.1

Проект для Render Free + PostgreSQL (Supabase Free). Без платного API карт и без ИИ API.
Администратор по умолчанию: **8051325598**.

## Что уже реализовано

- Telegram-меню с восемью готовыми CXZ-обложками; смена фото через админку.
- Проверка доступа сразу по кнопке «Найти бизнесы».
- Индивидуальные одноразовые ключи, привязанные к Telegram ID; отзыв ключей.
- 30 ниш и ввод своей ниши; произвольный город/регион текстом.
- 5 или 10 компаний за запрос, до 50 новых сохранённых компаний в сутки по Москве.
- Один активный запрос пользователя; одна последовательная очередь поиска на экземпляр приложения.
- Результаты, избранное, заметки, статусы клиента, CSV с BOM для Excel.
- Профиль, история поиска, остановка и кнопка проверки прогресса.
- Админка: всего/новые/активные за день и неделю, активации, первый/последний визит, поиски и результаты каждого, блокировка пользователей, ключи.
- Сохранение очереди, прогресса и результатов в PostgreSQL; продолжение по истечении аренды задания после перезапуска.
- Webhook с секретом; при недоступной базе Telegram получает 503 и может повторить доставку.
- Повторное сохранение одной компании не расходует лимит; операции сохранения защищены транзакцией и уникальным ограничением.

## Честный статус проверки

Проверены синтаксис Python, SQL-схема и 67 статических SQL-запросов. Локальные тесты проверяют фильтрацию, доступ, лимит на уровне правил, ссылки, отсутствие ложных результатов при неполной карточке, CSV-инъекции.
Реальный запрос «ремонт обуви Казань» вернул карточки; сайты в проверенных карточках обнаружены и исключены. Отдельно прочитана карточка с Yclients: поля сайта и бронирования доступны в публичном HTML. Реальная карточка мастерской «Эш вакыт» без опубликованных сайта и записи принята: отсутствие поля сайта дополнительно сверяется с загруженным блоком контактов HTML.

**Это первая рабочая сборка кода, а не уже размещённый бот.** Запуск Telegram, настоящие транзакции Supabase, одновременная работа пользователей и доступ к Яндексу именно с Render ещё требуют проверки после настройки аккаунтов. Четыре интеграционных теста PostgreSQL включены, но без отдельной тестовой базы пропускаются.

## Ограничения поиска

Проверяются поля сайта и записи, опубликованные в данных одной карточки Яндекса. Не выполняется поиск сайта во всём интернете, проверка 2ГИС/Google или сторонних соцсетей. Формулировка результата: «сайт и онлайн-запись не обнаружены в данных карточки Яндекса».

Карточка с неизвестной схемой, пропущенными обязательными полями (отсутствие urls допускается только при подтверждённом блоке контактов HTML), скрытыми контактами, закрытым бизнесом, сайтом или записью в результат не попадает. Ошибка/капча останавливает запрос; обход CAPTCHA, смена IP и прокси не используются.

Территория и ниша задаются поисковому движку Яндекса. Это пока не географический полигон и не строгая проверка принадлежности адресу: проверяйте адрес в карточке; поисковая выдача Яндекса иногда расширяет область. В текущей среде Яндекс может возвращать английские названия даже для русского запроса.

До 60 кандидатов / 12 публичных страниц выдачи на один поиск и до 15 минут на задание. Если подходящих меньше 5/10, выдаётся найденное. Это ограничение защищает бесплатный сервер. Результаты разных запусков одному пользователю не повторяются. Несколько пользователей могут получить одну компанию.

Лимит расходуется при сохранении новой карточки, которая сразу доступна в разделе результатов. При остановке/ошибке уже сохранённые компании остаются и учитываются. Скачивание/избранное лимит не расходуют. Если остаток менее 5, новый запрос недоступен до следующих суток.

## Запуск: шаг за шагом

### 1. Создайте Telegram-бота

В официальном @BotFather выполните `/newbot`. Токен не отправляйте в переписку и не кладите в репозиторий.

Аватар бота задаётся в BotFather отдельно. Обложки разделов уже в папке `assets`.

### 2. Создайте базу Supabase

1. Создайте проект на Free. Сохраните пароль базы в своём менеджере паролей.
2. Откройте SQL Editor → New query.
3. Скопируйте **весь `schema.sql`**, нажмите Run. Скрипт создаёт таблицы `cxz_*` и запрещает к ним анонимный доступ через Data API.
4. В панели Connect выберите PostgreSQL **Session pooler**, порт **5432**. Он подходит для длительно работающего сервера и IPv4.
5. Скопируйте строку подключения, замените `[YOUR-PASSWORD]` своим паролем. Если пароль содержит специальные символы, они должны быть URL-encoded. Добавьте `?sslmode=require`, если параметров ещё нет.

Пример формы (НЕ реальные значения):
`postgresql://postgres.PROJECT:ENCODED_PASSWORD@REGION.pooler.supabase.com:5432/postgres?sslmode=require`

Не используйте строку из примера буквально: хозяин/регион берутся в вашем Supabase. Не используйте anon key или service_role key вместо пароля PostgreSQL.

Для первого прототипа используется серверное подключение postgres. Оно секретное и не должно попадать на сайт/в Telegram/в логи. Таблицы включают RLS и не доступны клиентским ролям.

### 3. Загрузите проект в репозиторий

Распакуйте архив. В корне репозитория должны быть `app.py`, `Dockerfile`, `requirements.txt`, `render.yaml`, `schema.sql`, `assets` и остальные файлы проекта.

Используйте свой доступный GitHub/GitLab/Bitbucket-репозиторий, который можно подключить к Render. Если GitHub недоступен, подключите GitLab. Не загружайте `.env` или секреты. Файл `.env.example` содержит только примеры.

### 4. Создайте Render Web Service

- New → Web Service → подключите репозиторий.
- Runtime: Docker.
- Instance type: **Free**, не платный план.
- Health Check Path: `/health`.
- Один экземпляр/один сервис. Код не рассчитан на запуск нескольких независимых копий очереди одновременно.

В Environment добавьте:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен BotFather |
| `DATABASE_URL` | Строка Session pooler Supabase |
| `ADMIN_ID` | `8051325598` |
| `WEBHOOK_SECRET` | Случайная строка из 64 hex-символов |
| `KEY_PEPPER` | Другая случайная строка; храните её постоянно |

Для каждого секрета отдельно можно выполнить на своём компьютере:
`python -c "import secrets; print(secrets.token_hex(32))"`

Если разворачиваете через Render Blueprint (`render.yaml`), два секрета генерируются автоматически, ID уже указан. В обычном Web Service заполните их вручную.

`RENDER_EXTERNAL_URL` Render задаёт автоматически. Если он отсутствует, укажите `PUBLIC_URL=https://ИМЯ-СЕРВИСА.onrender.com`.

**Не меняйте KEY_PEPPER после выдачи ключей**: ранее выданные ключи перестанут распознаваться. Не устанавливайте второй экземпляр приложения с тем же токеном бота: он может перерегистрировать webhook.

### 5. Первый запуск

1. Дождитесь состояния Live и строки `CXZ ready` в логах.
2. Откройте бота → `/start`.
3. У администратора появится кнопка «Админ-панель», поиск доступен без активационного ключа.
4. Создайте ключ и проверьте активацию с другого Telegram-аккаунта, принадлежащего вам или тестировщику.
5. Запустите поиск на 5 компаний в своей нише/городе. Откройте 2–3 выданные карточки вручную, проверьте поля сайта и записи и адрес.
6. Добавьте компанию в избранное, напишите заметку, перезапустите сервис. Убедитесь, что данные сохранились.

Для локальной диагностики Яндекса (без токена Telegram и базы):
`pip install -r requirements.txt`
`python parser.py "ремонт обуви" "Казань"`

## Засыпание и бесплатные лимиты

Render Free может заснуть без входящих запросов и перезапуститься в любое время. `/health` предусмотрен для внешнего монитора, если вы решите его использовать. Никакой монитор автоматически не подключён. Периодические обращения не отменяют квоты и ограничения Render.

Сон/перезапуск не стирает данные в Supabase. Во время сна поиск не выполняется; после пробуждения очередь продолжится. Возобновление задания возможно после истечения его аренды (до 3 минут). Прерванная отправка Telegram-уведомления может повториться; сама карточка и списание лимита не дублируются.

Supabase Free может быть приостановлен после недели неактивности. Пока база недоступна, защищённые действия и поиск не работают; Telegram webhook отвечает 503. После восстановления базы повторите действие, если Telegram не доставил его заново. Постоянная база — не резервная копия: регулярно экспортируйте свои данные средствами PostgreSQL/Supabase. CSV сохраняет результаты, но не заменяет полный backup пользователей/ключей/очереди.

## Замена изображений

Админ-панель → Картинки → выберите раздел → отправьте фото. Telegram file_id сохраняется в базе. Исходные изображения из `assets` отправляются только при отсутствии сохранённой версии. Замену аватара делайте через BotFather.

## Что хранится и кто видит

Сохраняются Telegram ID, имя, username, первый/последний визит, активация, поиски и карточки. Администратор видит эти данные, заметки и статусы результатов. Полные секретные ключи доступа не сохраняются; в базе только хеш и короткая метка. Очередь входящих сообщений очищает тело сообщения после обработки. Бот не видит, что пользователь просто открыл чат, если тот ничего не нажал и не отправил.

## Тесты

`python -m unittest discover -s tests -v`

Для интеграционных тестов используйте **только отдельную пустую тестовую PostgreSQL**, задав `TEST_DATABASE_URL`.
**Тесты очищают все таблицы cxz_* в указанной тестовой базе. Никогда не указывайте рабочую базу.**

## Если что-то не работает

- Ошибка таблицы `cxz_users`: выполните `schema.sql` в нужном проекте Supabase.
- База не подключается: проверьте Session pooler 5432, пароль, SSL, состояние проекта.
- Telegram 401: неверный BOT_TOKEN.
- Нет админки: сравните Telegram ID с ADMIN_ID, нажмите `/start`.
- Ключ не подходит: он отозван/использован другим аккаунтом или изменился KEY_PEPPER.
- Поиск blocked: Яндекс недоступен/капча/неизвестная разметка; бот не подменяет проверку случайными результатами.
- Найдено 0: все доступные кандидаты имеют сайт/запись, ранее выданы, закрыты или недостаточно данных для проверки.
- Частичный результат после 15 минут: уже найденное сохранено. Бесплатный прототип ограничивает время задания.
